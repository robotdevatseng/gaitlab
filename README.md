# GaitLab 原型：離線單鏡頭步態分析（Wide-based Gait）

用一段「病人正面朝鏡頭走過來」的影片，在自己的電腦上算出步寬、步寬變異、步速、步頻、雙腳支撐期等指標，並產生報告。全部在本機運算，不上傳任何資料。

> 研究用原型，尚未與壓力步道或標記式系統做過驗證，結果不可作為臨床診斷依據。

---

## 最簡單的用法（建議）

1. **第一次**：以前已照說明書用 python3.11 裝好的，不用再裝。沒裝過的雙擊「安裝.command」（Windows：安裝.bat），等到出現「檢查通過 ✔」。Mac 第一次若說「無法打開」，請按右鍵 → 打開 → 打開。
2. **每位受試者**：建一個資料夾（例如 `S02`），裡面放兩個子資料夾 `正面`、`側面`，把 iPad 影片拖進去（檔名不用改）。
3. 雙擊「一鍵分析.command」→ 選 `S02` 資料夾 → 等它跑完。若跳出視窗要你點標記，依序點畫面上提示的標記，按 Enter。
4. 報告會自動打開；把 `S02/寄給研究者_S02.zip` 寄給研究者（不含影片，只有幾 MB）。

**更新程式**：程式放在 GitHub（robotdevatseng/gaitlab）。最簡單：到 https://github.com/robotdevatseng/gaitlab 按綠色的 Code → Download ZIP，解壓縮後取代舊的 gaitlab 資料夾（受試者資料夾請放在 gaitlab 外面）。若用 GitHub Desktop「Clone」下來，之後有新版時雙擊「更新程式.command」（Windows：更新程式.bat）就會自動抓最新版。更新後不必重跑舊資料，除非研究者要求；要重跑時姿態檔已有快取，一位受試者只要幾十秒。

**影片存放與重跑流程（Google Drive「步態研究_原始影片」）**

| 資料夾 | 放什麼 | 規則 |
| --- | --- | --- |
| `00_原始檔_唯讀` | iPhone／iPad 拍完直接傳過來的影片，依受試者分資料夾（`S02/正面`、`S02/側面`） | **只進不改**：不改檔名、不剪輯、不調色、不刪除。拍完用 AirDrop 或接線傳到電腦後直接放進來 |
| `01_分析工作區` | 從 00 **複製**出來的受試者資料夾，一鍵分析在這裡跑，`結果/` 與打包檔也在這裡 | 可以重跑、可以刪掉重來；壞了就從 00 再複製一份 |
| `02_影片清單` | 一張表：受試者代號、日期、每支影片檔名、正面／側面、穿鞋／赤腳、解析度、備註 | 每次拍攝當天填；重拍或作廢的影片也要記 |

重跑步驟（程式更新後、或研究者要求時）：

1. 更新程式（Download ZIP 或雙擊「更新程式」）。
2. 到 `00_原始檔_唯讀` 把該受試者資料夾**複製**到 `01_分析工作區`（若 01 已有同名資料夾，直接用它；裡面的姿態快取可以省時間）。先下載到電腦本機再分析，不要直接在雲端硬碟的串流資料夾裡跑。
3. 雙擊「一鍵分析」→ 選 `01_分析工作區` 裡的那個受試者資料夾。
4. 上一次的報告會自動搬到 `結果/…/舊輸出/<時間>/`，舊打包檔改名保留，不會被覆寫。
5. 把新的 `寄給研究者_XX.zip` 寄給研究者，並在 `02_影片清單` 記下重跑日期與程式版本（README 最上方或 GitHub 的 commit 編號）。

單支影片不合格（例如被編輯過、校正沒完成）時，程式只停那一支並在報告寫明原因，同一位受試者的其他影片照常分析。

現場尺寸寫在「設定.txt」（量測區 1.0 × 5.0 m、鏡頭高 1.2 m、側面標記距離 2.04 m）；佈置不同時才需要改。病人一律穿自己的平底包鞋；只有同仁驗證的赤腳組，把資料夾名稱加上「赤腳」（例如 `S04_赤腳`），程式會改用赤腳的高度修正。下面是完整說明與命令列用法。

## 1. 安裝（第一次，約 10 分鐘）

需要 **Python 3.10、3.11 或 3.12**（建議 3.11）。Windows 和 Mac（含 M 系列晶片）都可以。

```bash
# 1) 解壓縮後進入資料夾
cd gaitlab

# 2) 建立獨立環境（建議）
python -m venv .venv
# Windows：
.venv\Scripts\activate
# Mac：
source .venv/bin/activate

# 3) 安裝套件（這一步需要網路，之後分析就不需要了）
pip install -r requirements.txt

# 4) 自我檢查：用 20 趟已知答案的模擬行走確認計算正確
python tests/check_install.py
```

看到「檢查通過 ✔」就完成了。

## 2. 現場布置

| 項目 | 設定 |
| --- | --- |
| iPad 方向 | **直拍**（直的拿），人才會從頭到腳都在畫面內 |
| 鏡頭高度 | 三腳架上，鏡頭離地 **1.2 m**（量好記下來，分析時要輸入） |
| 錄影規格 | **4K / 60 fps**（設定 → 相機 → 錄影）；至少 1080p / 60 fps |
| 量測區 | 地上一個 **寬 1.0 m × 長 5.0 m** 的長方形，**近端距離鏡頭 2.5 m**（也就是 2.5–7.5 m） |
| 走道總長 | 鏡頭前 10 m 左右：病人從 9–10 m 處起步，走過量測區後在 1.5 m 處停下 |
| 地板標記 | 列印 4 張 ArUco 標記（`python -m gaitlab markers`），**標記中心的紅十字對準長方形四個角** |
| 背景與光線 | 背景單純、光線充足；病人褲管不要蓋住腳踝，穿自己的鞋 |

標記編號固定：**0 = 近左、1 = 近右、2 = 遠右、3 = 遠左**（左右以 iPad 畫面看到的為準）。

```
            3 ●───────────● 2      ← 7.5 m（遠端）
              │  量測區    │
              │ 1.0 x 5.0 m│
              │            │
            0 ●───────────● 1      ← 2.5 m（近端）

                  [iPad]            ← 0 m，高 1.2 m，直拍
```

**為什麼要這樣擺？** 我們用合成影像測試過：鏡頭只有 1.1 m 高、標記只有 15 cm 時，遠端標記偵測不到；量測區近端離鏡頭太近時，近端標記會跑出畫面。上面的設定（直拍、1.2 m、18 cm 標記、近端 2.5 m）在 1080p 和 4K 都能穩定偵測到 4 個標記。

列印標記時選「**實際大小 / 100%**」，印好用尺量黑框邊長應為 18 cm。

## 3. 拍攝流程（每位受試者約 3 分鐘）

1. 確認 4 個標記都在畫面內，按錄影。
2. 請病人從遠端起點以「平常的速度」朝鏡頭走，走過量測區後停下。
3. 停止錄影。**重複 3 趟**，每趟存成一段影片。
4. 三腳架和 iPad 全程不要移動（移動了就要重新校正）。

## 4. 分析

```bash
python -m gaitlab analyze trial1.mov trial2.mov trial3.mov \
    --floor 1.0x5.0 --cam-height 1.2 --subject P001 --out P001_result --overlay
```

- `--floor`：量測長方形 寬x長（公尺）
- `--cam-height`：鏡頭離地高度（公尺）
- `--overlay`：另外輸出標註影片，可以看程式抓到的骨架與每一步著地點（建議開，方便檢查）
- 程式會先在第一段影片自動找 4 個 ArUco 標記；找不到時會跳出視窗，讓你依序點 **近左 → 近右 → 遠右 → 遠左**，按 Enter 確認
- `--lateral heel`：步寬的左右位置改回舊版的腳跟點（預設是腳踝點；原因見第 7 節）
- 每次分析會先做**校正檢查**：從四個標記反推鏡頭高度，跟 `--cam-height` 差超過 8 cm 會在報告最上方警告（通常是標記間距量錯，或沒量中心到中心）

處理速度：一般筆電約每秒 10–15 格，10 秒的 60 fps 影片約 1 分鐘。


### 側面分析（站立期、雙腳支撐期、膝屈曲角度）

```bash
python -m gaitlab side S01_side_1.mov S01_side_2.mov S01_side_3.mov S01_side_4.mov --gap 2.04 --subject S01 --out S01_side
```

- `--gap`：側面兩張標記（ID 4、5）中心的距離（公尺）。本院佈置實測 **2.04 m**（預設值）；報告與 `side_summary.json` 會寫出實際使用值。這個值**只影響側面的步長與步速**（成正比，少 2% 就少算 2%）；**不影響**站立期、擺盪期、雙腳支撐期、步頻、步時、週期時間、膝角度，也不影響正面分析的任何指標
- 每支影片各自找標記；找不到時跳出視窗，點 4 號、5 號標記附近即可（自動吸附）
- 輸出 `side_report.html`、`side_summary.json`

方法（2026-11-13 改版）：先用「腳相對骨盆的前後位置極值」找到每一次站立（兩腳分得最開的時刻，最不受兩腿交會的雜訊影響），再在該時刻 ±0.2 秒內精修：腳跟往前速度降到門檻以下＋腳跟垂直落到地面 = 著地；腳尖往前速度升到門檻以上 = 離地。週期時間或站立期比例不合理（站立期不在 40–85%）的週期不採用。

左右腳一律是**受試者自己的左、右**：畫面未鏡像時，往畫面右方走 → 靠鏡頭的是右腳，往左走 → 左腳；靠鏡頭的腳站立時在畫面上位置較低，用來檢查模型的標記，不符就整趟對調。模型的標記以 0.25 秒中位數軌跡為參考，只修正短暫的對調，亂跳的影格作廢後內插。報告列出每趟的行走方向、是否鏡像（能自動辨識 ArUco 標記就確定不是鏡像）、單格對調數、作廢格數、是否整趟對調。

擬真合成資料（腳跟落地仍帶速度、站立末期腳跟上提、畫面邊界、0.4–1.0 m/s、30/60 fps）：站立期誤差約 −0.5（最大 1.2）個百分點、雙腳支撐期約 −1（最大 2.4）個百分點、步頻 ±0.2。**尚未用真人側面影片驗證**。

### 靜態站立測試（分離「模型偏差」與「沒踩準」）

受試者兩腳跟中心站在已知距離（例如 10、20、30、40 cm）的標記上，在距鏡頭約 3、5、7 m 各站穩 3 秒以上；另一人用捲尺確認後才開始錄。用同一次佈置的 `calib.json`：

```bash
python -m gaitlab static S01_static.mov --calib P001_result/calib.json --cam-height 1.2 --out S01_static
```

程式自動找出站著不動的片段，分別用腳跟、腳踝、腳尖算兩腳左右距離，輸出 `static.csv`；在旁邊填上實際距離即可比對。

### 輸出檔案（在 `--out` 資料夾）

| 檔案 | 內容 |
| --- | --- |
| `report.html` | 報告：主要指標、腳印圖、逐步步寬、品質檢查圖、逐步資料；用瀏覽器開啟、可列印成 PDF |
| `steps.csv` | 每一步的資料（研究用，Excel 可開） |
| `summary.json` | 各趟與合併的指標 |
| `<影片名>_calib.json` | 該支影片的地板校正結果（**每支影片各自校正**，記錄影片解析度） |
| `舊輸出/<時間>/` | 重跑時，上一次的報告、摘要、逐步資料會搬到這裡保留，不會被覆寫 |
| `*_pose.npz` | 姿態估計快取（重算時加 `--reuse` 可跳過姿態估計） |
| `*_overlay.mp4` | 標註影片 |

## 5. 指標定義

| 指標 | 定義 |
| --- | --- |
| 步寬 | 某一步腳跟著地點，到「前後兩次對側腳著地點連線」的垂直距離（GAITRite 的 base of support 定義） |
| 步寬變異 | 每一步步寬的標準差（SD）與變異係數（CV） |
| 步速 | 量測區內第一步到最後一步著地點的前進距離 ÷ 時間 |
| 步頻 | 60 ÷ 平均步時 |
| 雙腳支撐期 | 每個步態週期中兩腳同時站立的時間比例（側面分析） |
| 步幅時間變異 | 同一腳兩次著地間隔的 CV；正面拍攝的時間變異以此為主 |

足部行進角、腳跟距／骨盆寬：小驗證發現正面拍攝量不到（三位同仁足角都約 0°），已從報告移除，只留在 `summary.json` 供研究。

## 6. 運作原理

1. **姿態估計**：Google MediaPipe BlazePose，每格 33 個關鍵點，包含腳跟與腳尖。模型隨套件內建，完全離線。
2. **地板校正**：4 個角點算出單應矩陣，把影像上的點換成地板上的公尺座標。近端兩張標記通常能自動辨識；遠端兩張在畫面上很扁，常需手動點選（點在標記附近即可，程式會自動吸附到標記中心）。
3. **著地偵測（雙腳前後距離法）**：某腳著地時，它的**腳踝**領先對側腳尖的距離最大；以這個距離上升到 80% 振幅的時刻當著地時間（次影格精度）。2026-11 之前用腳跟點，但腳跟在深色鞋、褲管蓋住時有 20–40% 影格看不到，著地時間會晚 0.2 秒以上，整趟被誤判為步時不合而丟掉；腳踝點幾乎 100% 看得到。
4. **著地位置**：前後方向用**腳尖**（正面拍攝清楚可見）、左右方向用**腳踝**（著地後 0.05–0.15 秒的中位數，依約 9 cm 高度修正）。正面拍攝時腳跟被鞋子擋住，模型猜的腳跟點會在站立期往內漂約 1.5 cm，所以不用腳跟；腳踝點在站立期也會慢慢往內漂，剛著地時最接近實際落腳位置。
5. **挑出主要步伐序列**：所有候選著地中，用動態規劃找出「左右交替、步時 0.2–1.5 秒、步長 15–110 cm、相鄰兩步比例在 0.45–2.2 倍」且包含最多著地的一串；沒選上的就是多餘或錯誤的偵測（寬褲、腳被擋住時常見）。舊版是碰到一步不合就把整串切斷，一個假著地會讓整趟一步都不剩。另外排除：腳尖靠近畫面邊緣、著地附近偵測中斷、沒有往前的「假著地」。
6. **高度修正**：腳部關鍵點約在地面上方 3 cm，投影會讓距離放大約 Hc/(Hc−h)，程式依鏡頭高度修正。

## 7. 目前驗證到哪裡

**合成資料**（28 趟、相機投影模擬，含慢速、30 fps、雜訊、遮擋）：步寬誤差最大約 1 cm、步速最大約 2–3%、步頻最大約 1–2 步/分。

**第一批真人資料（2026-10，1 位健康同仁 × 3 趟，4K 直拍）**：

- 舊版的「腳速門檻」著地判斷在真人影片上失效（站立期 38%、雙腳支撐期 0%、左右步時 0.48/0.72 秒交替），原因是正面拍攝時腳跟離地投影到地板會像在往後退。已改為雙腳前後距離法。
- 改版後：步寬 7–13 cm、步速 95–108 cm/s、步頻 97–100 步/分、步幅 119–130 cm，左右步長一致，加 3 px 雜訊或遮擋 0.3 秒時步寬變動 < 1 cm。
- 獨立程式審查兩輪，修正 7 個會算錯的問題。

| 指標 | 狀態 |
| --- | --- |
| 步寬、步寬 SD | 合成資料已驗證。**膠帶小驗證（2026-10）**：腳跟點 10 cm → 9.1、25 cm → 19.6 cm；**腳踝點（2026-11 版）10 cm → 10.9、25 cm → 22.0 cm**。從 S03 影片直接量鞋子實際位置是 23.7 cm（同仁實際踩得比膠帶窄約 1.3 cm），腳踝點比實際落腳少約 1.7 cm、窄步多約 0.9 cm；正式驗證時需與壓力步道比對建立修正式 |
| 步速、步頻、步幅 | 同上 |
| 步長（左右分開） | 左右差異不可解讀（受左右腳形差異影響），請看步幅 |
| 步長（平均）、步幅 | 膠帶小驗證：60 cm → 59.3–60.2、120 cm → 118.1–119.3 cm |
| 步時變異 | 照腳印走仍有 6–8%（左右腳著地時間有系統差）；**改看步幅時間變異（3–4%）** |
| 雙腳支撐期、站立期 | 正面不提供；改由**側面分析**提供（合成資料已驗證，待真人驗證） |
| 足部行進角 | 正面拍攝量不到，已移除 |

**第二批真人資料（2026-11，5 位同仁 × 穿鞋／赤腳 × 3 趟）**：

- 舊版有 2 位同仁（S02、S03）穿鞋正面幾乎算不出步寬（9 趟中 7 趟 0 步）。原因是腳跟點在這兩位身上有 40–50% 影格看不到（深色鞋、褲管蓋到腳踝），著地時間用腳跟算會晚 0.2 秒以上，步時一長一短，整串被判「步時不合」丟掉。
- 改為腳踝點計時＋動態規劃挑序列後，30 趟每趟都有 5–9 次著地可用；五位的步寬：S01 10–12（赤腳 14–15）、S02 9–10（8–12）、S03 7–8（8–9）、S04 5–7（6–8）、S05 11–14（10–12）cm，穿鞋與赤腳大致一致。膠帶驗證數值不變（見上表）。
- 新增品質提醒「量測區內腳跟點可見比例」：低於 70% 時提醒下次把褲管捲到腳踝以上。校正誤差提醒門檻由 1.5 像素放寬到 3 像素（實測 0.3–1.7 像素對結果影響 < 0.2 cm）。
- 已知限制：正面拍攝的單步著地時間仍有 ±0.1 秒誤差，左右步時、步長會一長一短；請看**步幅**與**步幅時間變異**。側面分析的左右腳判斷待改寫。

**2026-11-13 更新（防呆與側面改版）**

- **影片不可編輯**：解析度不是相機原始規格（720p／1080p／4K）的影片**直接不分析**，並寫明原因。在相簿調曝光、對比、套濾鏡後，影片會被重新輸出且每支裁切大小不同（實測 2044–2116 像素寬，原檔 2160），畫面位置改變，校正就不成立。處理方式：相簿「編輯 → 回復 → 回復原狀」後重新 AirDrop。
- **每支影片各自校正**：不再三趟共用一份校正。同一次拍攝的後續影片，只有在解析度相同、且自動辨識到的標記位置與前一支相差 < 3 像素（證明鏡頭沒動）時，才沿用前一支沒辨識到的點；否則要重新點選。
- **算不出來的值是 null**，並在 `null_reasons` 寫明原因，不填 0；沒有分析的影片列在 `meta.not_analyzed`。
- **舊輸出不覆寫**：搬到 `舊輸出/<時間>/`；舊的打包檔改名為 `寄給研究者_XX_舊_<時間>.zip`。
- **側面**：五位同仁 20 趟，舊版站立期每趟 59–75%、雙腳支撐期 14–66%。原因有二：(1) 舊的左右腳修正是逐格貪婪比對，兩腿交會時一旦判錯就一路錯下去，反而把模型原本正確的標記改壞；(2) 事件是在整段影片上找腳速峰值，交會處的假速度造成多餘或漏掉的事件。改版後各受試者站立期平均 59–64%、同一人各趟標準差 0.7–3.4 個百分點；雙腳支撐期平均 19–28%、各趟標準差 3.5–7。**雙腳支撐期的趟間變異仍大，尚未與步道比對，請勿當作正式結果。**（以上是用舊輸出反推的標記位置重算，正式數值要等原始影片重跑。）

**低成本驗證方法（建議，尚未實作）**

不借步道也能先做的兩種參考標準，都只需要現有的 iPhone 和文具：

1. *步寬、步長 — 地面腳印量測*
   - 量測區鋪白色壁報紙或牛皮紙（1 × 5 m）；受試者鞋底腳跟中央貼一小塊沾了印泥或水性顏料的海綿（或踩過一盤滑石粉）。
   - 照正常流程拍攝，同一趟同時留下腳印。
   - 走完後在紙上標出每個腳跟印的中心，用捲尺量：相鄰兩步的前後距離（步長）、每個腳印到對側前後兩個腳印連線的垂直距離（步寬，與程式定義相同）。兩個人各量一次，取平均並記錄差異。
   - 每位受試者走正常、窄步、寬步各 3 趟，讓步寬涵蓋 5–30 cm；與程式逐步比對（Bland–Altman、ICC）。
   - 目標：10 位受試者、每人約 60 步，足以建立寬步距的修正式。
2. *站立期、雙腳支撐期 — 240 fps 慢動作人工逐格*
   - 側面另架一支 iPhone，貼近地面（鏡頭高約 10–15 cm）、慢動作 240 fps，對準量測區中段 2 m。
   - 與側面分析用的那支同時錄；開始時在兩支鏡頭都看得到的位置拍手或用閃光，做為時間對齊點。
   - 人工逐格標記每一步的腳跟觸地、腳尖離地影格（240 fps → 每格 4 ms）。兩位標記者獨立標，不看程式結果。
   - 由標記算出站立期、雙腳支撐期，與程式逐週期比對。
   - 目標：5 位受試者、每人約 20 個週期。
